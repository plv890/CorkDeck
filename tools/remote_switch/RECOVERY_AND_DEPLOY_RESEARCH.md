# Восстановление и обновление Switch — исследование 2026-10-05

HOME удалось исправить на стороне ПК, без установки ещё одного модуля.
Официальный sys-botbase содержит `UNUSED` с комментарием о подавленных
нажатиях HOME. Broker раньше отсоединял виртуальный контроллер после каждого
действия; проверенный обход сначала посылает `click UNUSED`, затем HOME через
тот же контроллер и только после этого отсоединяет его. Почему именно это
помогло на данном стенде, окончательно не установлено: наличие HID-защиты от
непреднамеренной HOME известно, но её состояние здесь не измерялось.

Источники: [sys-botbase util.c](https://github.com/olliz0r/sys-botbase/blob/master/sys-botbase/source/util.c),
[HiddbgNpadButton_Home](https://switchbrew.github.io/libnx/hiddbg_8h.html),
[HID Home input protection](https://switchbrew.github.io/libnx/hid_8h.html).

Проверено на консоли: hbmenu applet → HOME, затем Autorun из библиотеки → HOME
→ X → видимый диалог закрытия Autorun → A. Запуск игр не выполнялся; зависание
не имитировалось. После системного закрытия Autorun title ID стал пустым.
Снимки и журналы: 20261005T134505Z-22bca8b2 (hbmenu → HOME),
20261005T134753Z-d892bc49 (Autorun → HOME), 20261005T134820Z-3013998e
(диалог), 20261005T134849Z-0ff846c9 (закрытие),
20261005T134850Z-854a1b0a (нет приложения). Команда:

```text
broker.py --host 192.168.70.59 home-primed --expected-title 0548EABB35576000
```

После неё нужно оценить снимок, а не слепо посылать X/A: выделение HOME может
измениться. HOME возвращает в оболочку; само по себе это не завершение процесса.

Для резервного принудительного завершения существуют `pglTerminateProcess`,
`pmshellTerminateProcess` и `nsdevTerminateApplication`. PM в исходниках
Atmosphère завершает процесс через системный вызов; обработчик кнопок в игре
для этого не требуется. Предпочтительный следующий адаптер: получить PID и
title ID без debug attach, разрешить только Autorun 0548EABB35576000, повторно
проверить пару перед вызовом PGL, завершить именно PID и проверить его исчезновение.
Открывать службу только на время команды; не добавлять фоновый поток и не
включать GDB. Произвольные PID и системные программы в CLI не разрешать.
Наличие API не является аппаратной проверкой доступа на Ultra 3.0: этот
адаптер пока не реализован и не установлен. `appletPerformSystemButtonPressing`
также существует, но зависит от applet/debug-интерфейсов; для sysmodule без
applet-контекста это не универсальная готовая замена HOME.

Источники: [PGL API](https://github.com/switchbrew/libnx/blob/master/nx/include/switch/services/pgl.h),
[PM API](https://github.com/switchbrew/libnx/blob/master/nx/source/services/pm.c),
[Atmosphère PM termination](https://github.com/Atmosphere-NX/Atmosphere/blob/master/stratosphere/pm/source/impl/pm_process_manager.cpp),
[NS API](https://github.com/switchbrew/libnx/blob/master/nx/include/switch/services/ns.h).

Для обновлений выбран уже проверенный sys-botbase канал. Текущий модуль
пишет только отдельный тестовый NRO, до 2 МиБ. Доступ к рабочим файлам
`switch/wine` ещё нужно добавить. План протокола:

1. Манифест на ПК: относительный путь, размер, SHA-256 новой версии и ожидаемый
   SHA-256 старой. Разрешены только указанные файлы внутри switch/wine;
   абсолютные пути, `..`, двоеточия и выход за корень отклоняются на обеих сторонах.
2. Передача в отдельную staging-папку, проверка длины и SHA-256 на Switch.
   Для больших файлов — блочная передача с чтением буфера, а не побайтным recv
   и отдельным соединением на каждые 2 КиБ. Фактический текущий результат:
   192 КиБ с обратным чтением за 28.32 секунды, около 6.8 КиБ/с полезных данных.
3. Закрытие Autorun и подтверждение отсутствия процесса перед заменой.
   Старые файлы сохраняются, новые подставляются переименованием; журнал
   фиксирует каждый шаг и позволяет восстановить незаконченный пакет.
   Переименование одного файла не делает весь пакет атомарным.
4. Broker не запускает Autorun до проверки полного пакета. Первое испытание
   — безвредный файл в отдельном тестовом подкаталоге switch/wine и его откат.

Игры, Wine prefixes, реестр, Steam-сессии, пользовательские settings и сохранения
не входят в обычный манифест обновления сборки. Сам факт разрешения каталога
не означает, что нужно перезаписывать всё его содержимое. Большие DLL/runtime
payloads можно обновлять поштучно; ресурсы, встроенные в NRO/romfs, требуют
замены самого NRO. NRO оставляем для редких обновлений через DBI, как разрешил
пользователь. Рабочий forwarder и 39-bit путь сохраняются.

Twili предлагает push/pull, terminate и отладку, но опубликованная таблица
проверенных прошивок заканчивается гораздо раньше 21.1.0. sys-ftpd 1.0.5
заявляет обновление под 19.0.0; наша совместная установка FTP/GDB уже привела
к сбою и откатана. Эти сведения не доказывают несовместимость каждого модуля
отдельно, но не дают причины заменять стабильный минимальный канал прямо сейчас.

Источники: [Twili README](https://github.com/misson20000/twili),
[sys-ftpd release 1.0.5](https://github.com/cathery/sys-ftpd/releases/tag/1.0.5).

Исследование и работающая HOME-команда сохранены. 24 проверки на ПК прошли.
Прямое завершение через PGL и обновление рабочих ресурсов остаются следующими
задачами реализации, а не выполненными аппаратными проверками.
